140L LECTURE SLIDES — how this is put together
==============================================

WHY IT LIVES IN docs/
---------------------
`mkdocs gh-deploy` copies everything under docs/ verbatim into the gh-pages
branch. Files that are not .md are passed straight through — they are never
rendered, never added to the search index, and never listed in sitemap.xml.
Because nothing here is referenced from mkdocs.yml's `nav`, the slides are
effectively unlisted: reachable by URL only.

Do NOT add .md files under docs/lectures/. MkDocs would build them into real
site pages and index them for search, which is exactly what we don't want.
That is why this file is .txt.

The source PowerPoint decks are NOT in this repo at all.  They live in the
course Dropbox, and a deck is converted by rendering it to images in a
scratch directory and building from those.  Anything under docs/ is copied
to the public site on every deploy, so a 70 MB binary has no business here;
an earlier lectures-src/ held one and has been removed.

Live URL:  https://UCB-BioE-Anderson-Lab.github.io/cloning-tutorials/lectures/
Local:     mkdocs serve  ->  http://127.0.0.1:8000/cloning-tutorials/lectures/

A SECTION FILE
--------------
Each section is a standalone page. It contains nothing but its slides and
three script tags; deck.js injects all the chrome (control bar, presenter
panel, overlays, live regions) at load.

  <link rel="stylesheet" href="../../deck.css">
  ...
  <article class="slide" data-bg="section">
    <h1>Endonucleases</h1>
    <ul><li>...</li></ul>
    <template class="notes">Spoken narration for this slide.</template>
    <template class="desc">What is visually on the slide.</template>
  </article>

  <script src="../../deck.js" defer></script>
  <script src="lecture.js"    defer></script>

Order matters: deck.js first (it defines window.Deck), then lecture.js
(sets window.LECTURE), then any sequence files.

data-bg  omitted   -> white.  This is the default and almost every
                      content slide should use it.
         "lecture" -> --ground-lecture, the blue title slide of a lecture
         "section" -> --ground-section, the amber ground of a section divider

Those two are the only values deck.css defines.  The grounds come from
docs/lectures/style/palette.css, so a palette change moves every deck at
once; never write a colour here.  Earlier drafts had "blue"/"green"/"red"/
"black" grounds, which is why some notes still mention them.  They are gone:
the red one in particular said "we are skipping this", which is a thing to
say out loud rather than encode as a colour nobody is told the key to.

BUILDS
------
Any element with data-build="1", "2", ... appears one click at a time:

  <li data-build="1">Endonucleases</li>
  <li data-build="2">Exonucleases</li>

Optionally override the channels for that click:
  <li data-build="1" data-note="..." data-desc="...">


THE TWO TEXT CHANNELS
---------------------
Every step carries a narration channel (<template class="notes">, verbatim
from the original PowerPoint speaker notes) and a visual-description channel
(<template class="desc">). Both are mirrored into aria-live regions in every
mode, shown side by side in the W view, and reachable from JS:

  Deck.channels()   -> {note, description} for the current step
  Deck.steps()      -> all steps, e.g. to pre-render audio
  Deck.on(fn)       -> subscribe
  document.addEventListener("deck:step", e => e.detail)

The Speak toggle (S) pipes both through the browser's speechSynthesis.


AN ANIMATED SEQUENCE
--------------------
A long animation lives in its own file under seq/ and registers itself:

  window.Deck.sequence("rcr", function(slide){
    // build slide.innerHTML, then return:
    return {
      steps: [{note:"...", desc:"..."}, ...],   // one entry per click
      go: function(i, animated){ ... }          // render step i
    };
  });

Use it from a section with an empty slide element:

  <article class="slide" data-seq="rcr">
    <h1>Rolling Circle Replication</h1>
  </article>
  <script src="seq/rolling-circle.js" defer></script>

A sequence APPENDS its <svg> to the slide, so whatever headings and
bullets you author in the section file stay visible above the drawing.

Registered sequences in this lecture:
  exo53  displacement  t7rnap  exo35  nick   (seq/linear.js)
  rcr    rcamp                              (seq/rolling-circle.js)
  kunkel                                    (seq/kunkel.js)

The sequence supplies its own per-step channels, so notes and descriptions
for an animation live next to the geometry that draws it.


TRAPS
-----
Every one of these cost somebody an afternoon.  None of them errors; they all
just render wrong, or read wrong, and a source review will not catch any of them.

ENTITIES IN THE TWO CHANNELS.  deck.js reads both channels with
t.content.textContent, so an HTML entity in a <template class="notes"> or in a
data-note attribute is decoded by the parser and arrives correct.  A JS string
in seq/*.js is NOT parsed as HTML, so "&rsquo;" there is read aloud as five
literal characters.  Entities are fine in slide HTML and wrong in sequence
files.  The same file can legitimately contain both.

THE CONTENT BOX is x 110-1490, y 86-830: .slide minus its declared
86px 110px 70px padding.  On a slide with an h1 the art starts nearer y 206,
because the title is above it.  Both numbers are right, for different slides.
.slide is overflow:hidden, so ink past 1600x900 is silently cut off, while ink
merely in the padding is often deliberate (.src pins a citation at bottom:34px).

.slide .step IS display:flex WITH gap:14px.  Any inline element inside a step
line becomes its own flex item and opens a 14px gap on BOTH sides.  Wrap
everything after the arrow in one <span>.

.slide .cascade IS width:max-content.  A long <p> inside it has a max-content
width wider than 1380, which clamps the cascade to full width and silently
kills its margin:0 auto centring.  Cap the paragraph.

.site AND .mut ARE SCOPED TO pre.dna and do nothing inside a .step or a prose
line.

grid-template-rows:1fr IS NOT ENOUGH.  A grid row's automatic minimum is its
content, so one tall image claims the whole column and squeezes its neighbour
to a zero-height box, where it renders perfectly and is invisible.  Use
minmax(0,1fr).  Same family as every min-height:0 in deck.css.

SVG MARKER IDS MUST BE UNIQUE ACROSS THE WHOLE DECK.  Hidden slides stay in the
DOM, so two markers sharing an id both resolve to the first and the second arrow
loses its head.  Most seq files sidestep this by drawing arrowheads as paths.

AN OPEN SVG PATH IS IMPLICITLY CLOSED WHEN FILLED, so a traced open contour
fills as a wedge.  Use fill="none".

ART DRAWN FOR A GREY GROUND VANISHES ON WHITE.  Line art exported from an older
deck is often white strokes on transparency.  Recolour it into the palette when
it is line work in a few flat colours; keep it on a dark panel only when the
figure's own data colours overlap its line colours, where recolouring destroys
the data.

A CONTROL ON A SLIDE MUST NOT USE AN id.  Presenter mode clones the NEXT slide
into its preview pane, so every id on a slide exists twice the moment the slide
before it is showing, and getElementById can hand you the dead copy.  Find
things by class, inside the element the event came from: mark the widget with a
data- attribute, delegate the listener on document, and scope every lookup with
closest().  03-gene-synthesis.html's oligo calculator is the worked example.
Typing is safe -- deck.js already ignores keystrokes aimed at an input,
textarea, select or contenteditable, so a textarea on a slide does not walk the
deck.  Buttons and download links use .btn, defined in that same file.

A FILE THE SLIDE HANDS OUT GOES IN THE SECTION'S assets/ DIRECTORY, beside
img/.  mkdocs copies anything that is not .md straight through, so it needs no
registration; give the <a> a download attribute with the human filename.  If the
same bytes also live in a JS string on the slide (a clipboard button), say so in
a comment at both ends -- they will drift otherwise.

AUDITING
--------
tools/check_section.js walks a section step by step with settled frames and
reports ink outside the content box, how much of the box each step spans,
entities surviving into either channel, and console errors.  It writes a PNG per
step, which you should then actually look at.

    cd docs/lectures/tools && npm install     # once; node_modules is gitignored
    node check_section.js 02-dna-fabrication 05-homology.html /tmp/shots

Needs a running `mkdocs serve` and Google Chrome.  Two cautions: livereload
navigating the page mid-run produces false readings, so let things settle after
an edit; and a step under about 40 percent fill is usually a drawing laid out at
the source deck's scale and never grown into 1600x900, though the first beat of
a cumulative build is legitimately sparse.

ADDING A SECTION
----------------
1. Create the .html file in the lecture folder.
2. Add one line to lecture.js in the right position.
That is all — prev/next and the G menu both read lecture.js.

ADDING A LECTURE
----------------
1. Make 140L/NN-name/ with a lecture.js and a seq/ folder.
2. Write lecture.js for the new sections; it is the only place order lives.
3. Add a block to docs/lectures/index.html.
4. If the lecture should be reachable from the site, add a line under the
   Lectures heading in docs/index.md.  Everything under docs/lectures/ is
   unlisted until something links to it.


PRESENTING
----------
Advance with the arrow keys (or space / PageDown). Clicking the slide does
NOT advance — only the prev/next buttons in the control bar do, so a stray
click never moves the deck.

Use F11 (control-command-F on a Mac) rather than the in-page Full screen
button. Browsers drop the Fullscreen API on navigation and will not let a
page re-enter it without a gesture, so moving between sections would flash
out of full screen. F11 is the window manager's own full screen and survives
the hop. (If you do use the button, the deck re-enters full screen on your
next key press, so you get one brief flash per section change.)

Presenter view (P), the text channels (W), the elapsed timer, and the Speak
toggle all persist across section changes via sessionStorage. The timer
starts on the first section you open and keeps running for the whole lecture.
