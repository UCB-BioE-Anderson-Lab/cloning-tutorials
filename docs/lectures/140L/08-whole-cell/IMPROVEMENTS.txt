WHAT WAS MEASURED, AND HOW
--------------------------
Every image in the deck was measured for how far it is stretched: its
natural pixel width against the width it is drawn at in slide units
(the slide box is 1600 wide).  An upscale of 1.0 means the image is
drawn at its own resolution.

  >= 3.0   visibly soft at projection; reads as a blurry screenshot
  2.0-3.0  soft, noticeable on a big screen
  <= 1.8   fine

Word counts are body text only, notes excluded.  Both tables are at
the end of this file.  Re-measure with the script in
scratchpad/measure.js (puppeteer, waitUntil domcontentloaded — the
mkdocs livereload socket never lets a page go idle).

RUNNING THIS AS A SWARM
=======================
LANES ARE FILE-DISJOINT ON PURPOSE.  Each lane owns exactly one
section .html plus its own img/ and seq/ files.  No two lanes write
the same file, so they can run at once.

DO NOT LET ANY LANE TOUCH:
  docs/lectures/deck.css, deck.js, AUTHORING.txt
  docs/lectures/style/palette.css
  docs/lectures/140L/08-whole-cell/PLAN.txt
  docs/lectures/140L/08-whole-cell/lecture.js
Shared changes are made once, before the lanes start, or handed back
as a request.  PLAN.txt is merged at the end from each lane's report.

EACH LANE RUNS ITS OWN SERVER.  mkdocs livereload reloads every open
page whenever any file changes, and AUTHORING.txt records that a
reload mid-run gives false check_section readings.  With six lanes
editing at once, a shared server on port 8000 would make every audit
unreliable.  Copy the pattern from ~/Downloads/demoanimation/biofuel:
a check_section.js whose base URL comes from CHECK_BASE, and one
mkdocs or static server per lane on its own port.

EVERY LANE REPORTS BACK:
  - what it changed, slide by slide
  - the before and after upscale number for every image it touched
  - which notes it split, and proof the split is verbatim (the test
    used for slide 4a: card note plus click notes equals source note)
  - anything new it wrote that JCA has not approved: every caption,
    description and any narration
  - what it left alone and why
Nothing is committed by a lane.  Changes come back for review.

ORDER, IF RUN IN BATCHES RATHER THAN ALL AT ONCE:
  first   B1 (fluorimetry animation) and A1 (Brainbow pixels) — the
          two highest-value items, and A1 needs a decision from JCA
  then    D1, E1, E2 (the charts) — the most repetitive work, and the

  then    B2, B3, B4, B5, C1, C2, E4, F1
